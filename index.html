七猫免费小说 7.80 · 导出插件工程

qi-mao-book-export · 静态注入式章节解密导出
在已重打包的破解版 APK 基础上，静态注入一个导出插件（无 Xposed / 无 Pine / 无 native hook）， 直接借用 App 自身的解密器把缓存密文还原为可阅读的明文 txt，并支持分章勾选、整理全集。
Android 7.0+ (API 24) com.kmxs.reader smali 静态注入 DEX 解密复用 逆向分析 Frida / Xposed / smali 三方案

01这是什么

本项目围绕 七猫免费小说 7.80（包名 com.kmxs.reader）展开两件事：

导出插件（主线）
把 App 已缓存的加密小说章节，通过插件在本地解密并导出为纯文本 txt，可在手机内阅读或拷到电脑。实测一本书 3690 章 10 秒内全部导出，0 失败。
逆向分析报告
对原破解版 APK 做完整拆解：Pine Xposed 注入框架、40 个中文包名业务 Hook 类、Protect2C 壳（Dex2C/VMP）、原生 VIP 判定链路与三种改法对比。
关键突破：找到了正文加密点 com.km.encryption.api.Security（native 层 decrypt / decryptV2）， 插件通过反射调用它，把密文解成明文再落盘——所以导出的就是能直接读的字，而不是密文。

02注入点与工作原理

注入点位置作用
SophixStubApplication.attachBaseContextclasses10.dex启动插件
ChapterContentEntity.getContent()classes3.dex抓到每章密文
KMChapter.getChapterName()classes3.dex抓到章节名 / 书号 / 序号
com.kmxs.export.Bootclasses19.dex（新增）插件本体

数据流

App 缓存密文
   → ChapterContentEntity.getContent() 抓取密文字节流
   → com.kmxs.export.Boot 反射调用 Security.decryptV2(密文)
   → App 自带 native 解密器还原明文
   → 按 书号/章号 写入 /sdcard/Download/QimaoBooks/books/<书号>/<章号>.txt
   → ② 整理成 全集/<书号>_N章.txt

思路和原破解者改 VIP 一致：直接改 smali 字节码，不引入任何 hook 框架，因此不触发反 hook 检测、不会闪退。

03悬浮球面板（可见入口）

安装启动后，每个页面右侧偏下有一个橙色圆形「导/出」悬浮球，可拖动且位置会被记住。点击弹出：

七猫导出插件
目录: /sdcard/Download/QimaoBooks
已导出 N 章 / M 本;  App 缓存 K 个文件

① 导出章节 (可勾选 / 全选)   ← 像原版一样选章导出
② 整理成全集 txt
③ 复制导出目录路径
④ 打开缓存目录              ← 文件管理器 / 内置浏览器
⑤ 重新选择导出目录
⑥ 修复密文 (重新解密已导出文件)
⑦ 隐藏悬浮球 / 显示悬浮球
关闭

进入任意带 Setting 字样的页面，面板也会在该页列表末尾追加一行「七猫导出插件」入口。

04分章勾选导出

  • 选书：列出 App 已缓存的全部书（KmxsReader/books/ 下每个目录，显示书号 + 章数）。
  • 勾章节：进入章节清单（ListView + 复选框，几千章也流畅），顶部有 全选 / 全不选 / 导出选中 / 搜索。
  • 点「导出选中」后，选中章节解密写入 books/<书号>/，并合并出 _选中N章.txt。
推荐用法：先在七猫里「全本下载」想导出的书 → 悬浮球 ① 全选 → 导出选中 → ② 整理成全集 txt → 连电脑拷走。

07VIP 链路与三种改法（来自分析报告）

会员状态由服务器下发加密串 → 客户端 UserVipModel.decodeVipResponse() 解密 → 判定 status=="1" 即会员。所有可行改法都在「解密之后」动手：

方案需要 Root持久性被检测风险难度
Frida 注入 vip_hook.js是每次注入高低
Xposed 模块 VipHookModule.java否（LSPatch）永久中中
smali 硬改 UserVipInfoResponse否永久低高
报告结论：先 Frida 验证 hook 点正确，再改成 smali 硬改重打包最稳——它改的是业务代码而非 hook，天然规避 libhook-check.so / libProtect2C.so / libpinesafecheck.so 等所有反调试检测。注意：本地改状态只能影响客户端行为，服务器强校验的内容（如服务器不下发的 VIP 正文）仍拿不到。

09已知边界

  • 个别「整本打包」缓存（文件名 0.txt）解不开，插件自动跳过并计入 fail，不影响逐章导出。
  • 个别 VIP 章节在阅读器里显示为 base64（App 自身解密未通过）→ 同样导不出，属破解版限制。
  • 插件 dex 要求 Android 7.0 (API 24)+（D8 不脱糖接口默认方法）。
  • chapters/ 里 v1 遗留密文，点 ⑥ 会自动重新解密覆盖。
